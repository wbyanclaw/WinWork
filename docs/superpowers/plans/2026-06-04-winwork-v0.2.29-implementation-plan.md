## 1. 实现顺序（按主规格 5.2 / 5.3 优先级）

### 第一刀：invoke 闭环审计（地基，不动则后面全埋雷）
来源：主规格 5.2

**目标**：保证不存在"前端能调但后端没注册"的断链

**实现步骤**：
1. 写 `scripts/audit-invoke.sh`，逻辑：
   - `grep -nE "invoke\\(['\"][^'\"]+" src/index.html src/js/ -r` 取出前端所有 invoke 名（去重）
   - `grep -nE "^\\s+[a-z_]+," src-tauri/src/lib.rs` 取出后端已注册 handler 名（去重）
   - `comm -23 frontend.txt backend.txt` 算差集
   - 任何非空差集 = 0 容忍
2. 跑一次，记录 baseline 差集（已知缺：trigger_install / wiki_ingest / wiki_query / wiki_lint）
3. 这些差集在 L1/L2/L3 实现中分别消化
4. 验收点 = AC-102

**风险**：L1 / L2 / L3 的实现中每加一个 invoke，必须跑一次 audit-invoke.sh，否则会埋新雷。

### 第二刀：L0 回归测试（保证现有 UI 骨架不退化）
来源：主规格 4.2

**目标**：v0.2.28 的 B-scheme 骨架在 v0.2.29 不能回退

**实现步骤**：
1. 跑 headless 截图 → 4 胶囊 + 双 section + 底部按钮 + 中间对话 + 右侧滑出
2. 跑 `node --check` 提取所有 inline `<script>` 块（自动脚本）
3. 跑 AC-001 / AC-002 / AC-003

**这一刀大概率不写新代码**，只验证。如果 v0.2.28 的 B-scheme 本身有未暴露的 bug（比如异步加载时序问题），在这一刀先消化。

### 第三刀：L1 实施（wind-cli 入口可用）
来源：主规格 3.1 L1

**目标**：trigger_install 链路完整 + 状态回 UI 是结构化

**实现条目**：
| ID | 位置 | 改动 | 验收点 |
| --- | --- | --- | --- |
| L1-1 | `src-tauri/src/lib.rs:262-294` invoke_handler | 注册 `trigger_install` handler | AC-102 |
| L1-2 | `src-tauri/src/wind.rs` | 新增 `pub fn trigger_install()` 实现：调 `opener_open_url("https://github.com/wbyanclaw/wind-cli/releases/latest")` 打开下载页 | AC-102 |
| L1-3 | `src/index.html:824` | 已有 `invoke('trigger_install')`，无需改 | AC-102 |
| L1-4 | `src/index.html:824` 错误处理 | 当前 result.ok 判断是 brittle，加 try/catch + 弹用户友好提示 | AC-101 / AC-103 |
| L1-5 | `scripts/audit-invoke.sh` 复跑 | 差集必须为空 | AC-102 |

**风险**：
- GitHub releases/latest 链接的稳定性（如果被改路径就 404）。缓解：fallback 到 wind-cli 固定 release tag URL。
- Windows SmartScreen 弹窗会拦下载页（不是代码问题，但用户体感差）。规格没要求处理，记入"已知未覆盖"。

### 第四刀：L2 实施（工作区最低可用交互）
来源：主规格 3.1 L2

**目标**：查询 / 预览 / 搜索 / 基本文件查看链路全部成立

**实现条目**：
| ID | 位置 | 改动 | 验收点 |
| --- | --- | --- | --- |
| L2-1 | `src/index.html:618 showFileContent` | 替换 `<pre>` 渲染：检测 .md / .markdown 后缀 → `marked.parse(content)` 渲染；其他后缀保持现有 | AC-203 / AC-204 |
| L2-2 | `src/index.html:289-306` 左栏 | 在 fileTree 顶部加 `<input id="fileSearch" placeholder="搜索文件...">` | AC-205 |
| L2-3 | `src/index.html` 新增 | 监听 fileSearch input 事件，过滤 `loadFileTree` 已加载的 entries，hide 不匹配的 div | AC-205 |
| L2-4 | `src/index.html` 新增 | 加"搜索结果数"提示（"N 项匹配"） | AC-205 |
| L2-5 | `src-tauri/src/lib.rs:262-294` invoke_handler | 注册 `search_files` handler（如果选择后端搜索；如果纯前端 filter，可省） | AC-205 |
| L2-6 | `src-tauri/src/wind.rs` | （可选）`pub fn search_files(query: &str) -> WindResult`，用 wind-cli 的 find / grep 子命令 | AC-205 |
| L2-7 | `scripts/audit-invoke.sh` 复跑 | 差集必须为空 | AC-205 |

**关于 L2-5 / L2-6**（后端 vs 前端 filter）：
- 主规格 5.3 优先级 = 预览 > 搜索 > 查询
- 最小集 = 文件名模糊匹配 = 可纯前端实现
- 推荐: 先 L2-2/3/4 纯前端 filter 落地，AC-205 走通；如果工时允许再加 L2-5/6 后端增强
- 决策点：开工前问 @ruler 拍

**风险**：
- marked.js 异步加载竞态：如果文件点击发生在 marked 加载完之前，会 fallback 到 `<pre>`（虽然 index.html 已经引了 lib/marked.min.js，但要确认加载顺序）
- 搜索性能：workspace 文件数 > 1000 时纯前端 filter 会卡。缓解：debounce 200ms；如果还卡再上后端
- 搜索 UX：当前"隐藏不匹配"会让用户以为文件被删了。要加"显示全部"重置按钮

## 3. 跨组件依赖边界

**v0.2.29 不需要 wind-cli 侧改动**：
- L1 trigger_install 调的是 GitHub releases 链接，跟 wind-cli 子命令无关
- L2 preview / search 是 winwork 侧纯前端改动
- AC-205 搜索如果走纯前端 filter，连 wind-cli 都用不到

**v0.2.29 不涉及**：
- 知识库子命令（属于 v0.3.0）
- wind-cli 版本号硬要求（v0.2.29 兼容当前 wind-cli 0.3.0）

## 4. 已知技术债（不在 v0.2.29 范围，但记下）

- v0.2.27 那些 4 处反引号 escape 已修，但 src/index.html 还是单文件巨型 HTML（80KB+），未来要拆模块
- index.html 里 `parseWindVersion` 的正则对 "wind 0.3.0" 形式生效，但对纯 "0.3.0" 形式不生效。要在新测试里覆盖更多 case
- Cargo.lock 有未提交修改（应该是 v0.2.28 cross-compile 引入的），v0.2.29 第一刀顺手收掉
